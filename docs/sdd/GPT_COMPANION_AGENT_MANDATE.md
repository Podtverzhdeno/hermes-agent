# Hermes GPT: долговременный контракт инженерных агентов

**Статус:** действующее инженерное задание (не свидетельство, что исполнители запущены)  
**Дата фиксации:** 2026-11-22  
**Изменение:** GPT Companion PR #12 — review-only, read-only kernel

## 1. Цель и критерий истины

Цель: сделать процесс выполнения задач Hermes, GPT и десятков параллельных агентов **проверяемым, диагностируемым и восстанавливаемым** вплоть до каждого внешнего эффекта и шага принятия решения. Отчёт «агент подумал и завершил» не является доказательством.

Ключевой результат не «агент не молчит», а **каждый запущенный run имеет подтверждённый источник, границы полномочий, owner/fence, исполненный или незавершённый шаг, причину остановки с уровнем уверенности, безопасное действие по восстановлению и ссылку на независимый артефакт**.

Любая формулировка «готово», «прошли тесты», «наблюдаю всё», «починил локально» должна содержать точные доказательства: SHA, job/check ID, тестовую команду + среду, ack/receipt от адаптера, ревизию SDD. Если доказательства отсутствуют — статус `unknown / unverified`.

## 2. Что категорически нельзя скрывать

- Отсутствие доступа к реальному рантайму/Local MCP (`Session terminated`) не превращать в заявление о мониторинге локального браузера.
- Наличие сообщения в ChatGPT, страницы или браузерного спиннера не означает, что вызов инструмента завершился.
- Неожиданное завершение процесса, разрыв стрима, истечение lease и неизвестный внешний эффект — разные причины.
- Сомнительную cause классифицировать как `hypothesis`, не выдавать за `confirmed root cause`.
- Нельзя запускать второе внешнее действие с тем же эффектом только потому, что не пришёл ответ от первого.
- Успех тестов на SHA A не доказывает корректность SHA B, а CI skipped/in_progress не равно success.
- Репозиторий fork в main версии Hermes 0.6.0 (2026-04-01) и browser plugin, разработанный для более новых выпусков, не гарантированно совместимы. Не обходить version gate.
- Не отключать подтверждения, safety controls, consent, лимиты провайдера; не использовать чтение ChatGPT DOM для обхода официальных путей интеграции.

## 3. Работа десятков агентов: разделение полномочий

| Роль | Разрешённый вклад | Чего не делает | Независимый gate |
| --- | --- | --- | --- |
| A0 coordinator | назначает ownership и приоритет, фиксирует spec/dag и конфликт | не объявляет результат verified по своему же отчёту | policy + внешний verifier |
| GPT observer | принимает разрешённые *metadata only* события, диагностирует неполные трассы | не выполняет инструменты, не одобряет и не повторяет эффекты | auth ingress + event chain |
| Hermes adapter engineer | реализует version-pinned hooks и durable outbox | не подменяет согласие пользователя | capability + compatibility tests |
| Browser adapter engineer | подключает opt-in контекст/события, если поддержано | не читает скрытые чаты и секреты | consent + source contract |
| Reliability engineer | синтезирует отказ и воспроизводит его | не объявляет причину без evidence | fault injection и replay |
| Executor A1–A5 | делает локальный scoped код/тесты/артефакты | не пишет в чужие worktrees/ноты | worktree ownership + exact HEAD |
| Independent verifier | проверяет CI/SHA/приёмку/receipt напрямую | не принимает самоотчёт как evidence | доверенный канал GitHub/host |
| Security reviewer | проверяет scope, auth, логи, retention и prompt injection | не расширяет собственные полномочия | human review для R2/R3 |
| SDD steward | сводит ADR, версии контрактов, риски, postmortem | не перезаписывает чужие решения без аудита | reviewer + CAS |
| Release operator | управляет rollout/rollback/kill switch | не сливает неготовые ветки | матрица G0–G8 |

Наличие 10–100 агентов не даёт права 10–100 агентам менять один и тот же объект. Одному `resource_key` в момент времени соответствует один владелец lease + монотонный fence. Все другие агенты могут формулировать предложения, но записывают их в собственные ветки и отдельные ADR/PR.

## 4. Обязательный атомарный журнал инцидента

Для *каждой* остановки/зависания заполнять метаданные без содержимого приватной переписки:

```
incident_id: <opaque-id>
run_id: <opaque-id>
task_id: <opaque-id>
actor/source: <authenticated-source-id>
attempt/fence: <number>
expected_stage: <stage-id>
observed_last_stage: <stage-id>
last_receipt_at: <server-time>
last_progress_at: <server-time>
subject_revision: <exact git-sha or version>
external_effect: none | reserved | acknowledged | unknown
candidate_causes: [<normalized-code>]
root_cause_confidence: confirmed | probable | hypothesis | unknown
proof_refs: [<opaque artifact/job/receipt refs>]
next_safe_action: <specific bounded action>
auto_retry_allowed: false
owner: <responsible-role>
followup_gate: <objective test>
```

`auto_retry_allowed` в этом шаблоне `false`, пока доверенный task ledger/permit service не проверит идемпотентность, approval, lease и состояние внешнего провайдера. Журнал **не содержит** API keys, access tokens, session cookies, полномасштабные prompts, приватные письма или тело вывода.

## 5. Работа с остановкой: обязательный порядок

1. **Идентификация:** зафиксировать run/attempt/source/event source revision; не принимать смешанные истории разных агентов.
2. **Доверие:** есть ли auth источника? Полна ли последовательность? Не было ли replay/backfill/временного скачка?
3. **Внешние эффекты:** если есть `effect_reserved` и нет receipt, остановить новые внешние writes, запросить read-back у провайдера, зарезервировать reconciliation.
4. **Права:** проверить точную политику, expiry approval, thread/worktree ownership и fencing в доверенном ядре, а не по сообщению модели.
5. **Сбои:** проверить network/Auth/CORS/429/timeout/schema/version/hook/CI/LLM context/host process/SQLite независимо.
6. **Гипотезы:** отделить причину, корреляцию, простой таймаут и наблюдательную слепую зону. Указать альтернативную гипотезу.
7. **Фикс:** минимальный change set в своей ветке, воспроизводимый regression test, rollback strategy.
8. **Приёмка:** независимые тесты, CI на exact SHA, согласие для привилегированных действий, обновление ADR.
9. **Возобновление:** только на основании подтверждённого состояния, с сохранённым новым fence и checkpoint. Никакой «просто перезапусти этот промпт».

## 6. Переход на новую сессию/агента

Передача работы не зависит от окна ChatGPT. Сменный агент обязан получить:

- `goal/spec_version`, scope, forbidden operations, родительский DAG, бюджет;
- текущие `task_id`, `attempt`, `fence`, `worker/owner`, `pending_approval`;
- source revisions и манифест изменённых файлов;
- пройденные **на этом SHA** тесты и ещё не пройденные gates;
- неразрешённые внешние эффекты, idempotency keys и provider receipt refs;
- известные инциденты и проверяемые next actions;
- раздельные состояния: `implementation`, `integration`, `live monitoring`, `production`.

Новый агент не должен «вспоминать» скрытые рассуждения прошлого агента. Он читает durable ledger, SDD, артефакты и evidence; при несоответствии приостанавливает изменения.

## 7. Стандарты оценки идей

Оценивать идеи не по сложности/новизне, а по измеряемому снижению рисков. Каждый ADR должен описывать минимум: **зачем**, failure mode, альтернативы, data/control boundary, предположения, угрозы, стоимость владения, путь к воспроизведению, критерий отмены и субъективную уверенность. Не писать «10/10» без подтверждённого SLO/результатов испытаний.

**Порядок приоритетов:** безопасность внешних эффектов и разграничение полномочий > достоверность конечного результата > восстановление и сохранность > видимость причин > производительность > интерфейсное удобство. Для нескольких десятков агентов — отдельно считать деградацию от конкурентных writes, contention SQLite, callback duplicates, GitHub API 429, starvation и вызовов неподходящих версий hooks.

## 8. Выполненное и не выполненное на дату фиксации

**Реально реализовано в GPT Companion PR #12:** безопасное хранилище неавторитетных событий, идемпотентность `event_id`, source-local sequence/failure detector, границы worker/gateway, обработка позднего backfill и clock skew, fake-completion guard, metadata allowlist, SQLite chain, Python CLI для разового расследования и локальный opt-in read-only polling watcher (не установлен и не запущен). Прогон 52 offline tests на Python 3.13.5; 100 source **синтетически**, не 100 действующих GPT-агентов.

**Не реализовано и не объявляется существующим:** живое подключение к ChatGPT/browser/Hermes hooks, auth ingress, длительный watchdog, операторский сервер/дашборд, автофиксы, verified external effects, распределённый consensus, автоматическая синхронизация в Obsidian, сквозные prod тесты; локальная связь с владельцем через MCP не подтверждена.

**Соседние рабочие ветки, не трогать:** `feat/autopilot-durable-ledger-20261122`, `feat/skill-harness-contracts-20261122`. После ревью соединить через versioned adapter (не смешивать журналы/permissions/leases). Пакетное обнаружение модулей в `pyproject.toml` при объединении должно включать `autopilot` **и** `gpt_companion`.

## 9. Следующее разрешённое действие без нового решения владельца

При наличии доступного локального Hermes и подтверждённого права на работу: выполнить **только read-only inventory** версий gateway, плагинов, hooks, browser extension, MCP connectivity, profile, API mode; записать хеши конфигурации без секретов, актуальный HEAD и номера CI. Изолированно проверить адаптеры на fake-данных. Выявленные реальные проблемы оформить incident/ADR и свой PR. До достоверного разрешения конфликтов между инструментами, агентами и источниками — никакого самостоятельного деплоя/мерджа/автоматического контроля браузера.

## 10. Стоп-критерии и отчётность

Завершить конкретный этап можно **только** при наличии: test evidence, exact revision, risk review, отрицательных сценариев, описания оставшихся ограничений и назначения следующего owner. Если отсутствует доступ к реальному источнику — этап `blocked_on_environment`, а не `done`. Любое превышение времени, количества попыток или бюджета — диагностируемый status, не повод незаметно увеличивать лимит.

Этот файл — сохраняемое **в репозитории** задание для других агентов, а не утверждение, что одна чат-сессия или модель получила вечную память либо может работать круглосуточно без внешнего процесса.
