## Reproducible failure stories (not claimed incidents)

**F01 / cross-session permission routing.** Start ACP sessions A and B, each producing a dangerous command requiring approval; interleave the callback installation and execution; verify recipient session ID and exact action digest. A false positive is any permission request shown to the wrong client. Repair is not accepted until the suite runs in the real repository with nested executor paths.

**F02 / silent browser suspension.** Kill the MV3 extension worker while its panel is visible. The native host and Autopilot ledger must retain all work; on reactivation, observer resumes from durable cursor. It must neither replay model calls nor infer task failure from the worker disappearing.

**F03 / ambiguous mutation.** Reserve an external effect, allow the remote side to commit, drop the response, terminate the worker. Required outcome is `needs_reconciliation`, not automatic retry. Evidence must include external read-back with an independent receipt or unresolved owner decision.

**F04 / 30-agent replay stampede.** Simulate shared provider HTTP 429 across 30 agents. Required outcome: coordinated token bucket, Retry-After and jitter, parent budget conserved, bounded queue.

**F05 / spurious green.** CI passed at SHA A; concurrent worker changed branch to SHA B. Required outcome: no success; old check remains evidence for A only.

**F06 / lost telemetry.** Drop a source event and reorder timestamps. Required outcome: `OBSERVABILITY_GAP`, not fabricated causal chain or task failure.

## Deep follow-up audit: 2026-11-22, ACP noninteractive security boundary

**E13 — OBSERVED critical:** `tools/approval.py` has a noninteractive branch where dangerous-command and combined guards return approved if neither CLI nor gateway mode is set. ACP can run in such a context; this could make prior approval callback wiring irrelevant. The same module also honors ambient `HERMES_YOLO_MODE` / `approvals.mode=off`, and global remembered pattern approvals which may apply outside the intended ACP session. A dedicated `enforce_callback` flag and scoped terminal bridge were added to draft PR #3; when enforced, callback is mandatory and only `once` is accepted. This is a *candidate mitigation*, not a verified complete tool authorization boundary.

**E14 — OBSERVED interface mismatch:** `prompt_dangerous_approval()` passes `allow_permanent` keyword, whereas ACP `make_approval_callback()` originally accepted only positional command and description. A strict callback would raise TypeError and be interpreted as deny. Draft PR #3 adds the named argument and omits the permanent option in one-time mode.

**E15 — OBSERVED lifecycle issue:** ACP permission tool call used fixed ID `perm-check`; concurrent UI requests risk ambiguous correlation. Draft PR #3 switches to unique random tool-call ID, cancels outstanding future on timeout/error and denies malformed/unknown options.

**E16 — HISTORICAL CONTEXT, NOT LIVE VERIFIED:** Previous local Hermes smoke test (2026-11-11) referred to `C:/Users/Vadim/Tunnel/chat-launch-smoke-desktop-test/web-extension`, sibling `web-companion`, `bridge-config.json`, version `0.6.6`, port `18763`, and a stale heartbeat.
